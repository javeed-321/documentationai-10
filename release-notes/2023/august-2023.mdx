## Loyalty

### Improved purchase offer idempotency

We’ve improved the idempotency of the `purchase_offer` call of the Reward Stores API by adding a `request_id`. Previously, if you were experiencing delays with processing a `purchase_offer`  and resubmitted the request, the result was multiple offer issuance. Now, if you send in a second request with the same `user_id` and the new `request_id` while we are still processing the first request, we will send back a 409 error code.

*Please contact your Customer Success representative to enable idempotency. Our [API documentation](https://domains-connecteast1.ent-sessionm.com/offers/swagger/ui/index#/) has been updated with this change.*

## Campaigns & Content

### Configurable API response for campaigns requiring opt-in

Campaigns requiring opt-in currently return in the API 24 hours before the opt-in Start Date/Time. We’ve added a new setting that lets you control this behavior. When this setting is enabled, opt-in campaigns **won't** return in the API until the opt-in Start Date/Time. By default, this setting will not be enabled, and campaigns requiring opt-in will continue to return in the API 24 hours before the opt-in Start Date/Time.

*Please contact your Customer Success representative if you would like this setting activated.*

## Reporting & Analytics

### Timezone adaptation

Insights reports data in UTC, which for some users  especially those in countries with larger time offsets  yields daily data aggregations that do not fully correspond to the local customer behavior. For instance, a "sign up and get a discount" campaign starting on a Saturday at midnight in Indonesia may create a spike in new members on the *previous* Friday in Insights.

We are now introducing the ability to add an offset to the data feeding the Insights dashboards. A single timezone offset is available for all dashboards. For countries or brands operating across multiple timezones (e.g. the United States), you would need to select the most appropriate timezone for the reports. This is an optional configuration, and all Insights dashboards will continue to be shown in UTC, unless otherwise requested.

*Please reach out to your Customer Success representative to have this feature activated.*
