## Custom Action Overview

Custom action is needed when you want to extend the functionality of your automation framework beyond what default actions provided. Automation engineers and developers can write custom actions for incorporating any application specific requirements.

You can create custom actions in algoQA to simplify complex processes. For example, you can merge multiple steps into a single action, such as logging in with just one step instead of entering a username, password, and clicking the login button separately. Custom actions provide flexibility to extend the functionality of algoQA. You can import your existing methods into algoQA and use them as custom actions to enhance your automation capabilities.

Note that the custom action name should not be exactly the same as the default action name, which means the custom action name must be unique.

   <Callout kind="info" collapsed="false">
     The code analysis report can also be generated after creating a new custom action and saving the code. If code analysis has not been performed previously for the project, the platform automatically analyzes the project and displays the report, allowing you to identify duplicate methods, similar logic, and optimization opportunities. Since analysis can only be performed once per project, subsequent custom action creations will not trigger a new analysis.
   </Callout>
4. Once the analysis is completed, a Project Analysis Reports pop-up will appear, confirming that the project report is ready for review. Click View Report to open the analysis report, or Close to dismiss the pop-up and continue working in the project.
5. After clicking **View Report**, the **Analysis Report**page opens, displaying the results of the code analysis. The report provides insights such as:
   - **Exact Matches** – Identifies groups of methods with identical implementations across files.
   - **Similar Matches** – Highlights methods that contain similar logic and may be candidates for consolidation into reusable custom actions.
   - **Unused Methods** – Lists methods that are not referenced anywhere in the analyzed files.
   - **Files** – Displays the total number of files available.
     <Image src="https://s3-ap-south-1.amazonaws.com/ind-cdn.freshdesk.com/data/helpdesk/attachments/production/1070044040298/original/-o68grcZ2ZHTawKRmo4CDG4bPRnbDSx4iA.png?1781518551" width="1491" height="765" />
6. Use this report to review duplicate logic, identify reusable components, and optimize custom action creation.
7. The Code Analysis Report can also be accessed directly from the Custom Actions List screen by clicking View Analysis Report. This allows you to review previously generated analysis results, including exact matches, similar matches, unused methods, and analyzed files, without needing to run the analysis again.

   \\
   <Callout kind="alert" collapsed="false">
     In the Custom Action List screen, if a method name is displayed in red, it indicates that the method is no longer mapped to the custom action. This can occur when there are changes to the method parameters. In such cases, the mapping must be manually corrected.
   </Callout>
   Similarly, if a file name is displayed in red, it indicates that the corresponding file has been deleted from the project.\\
8. If the analysis report identifies duplicate or similar methods, you can click Optimize All to automatically consolidate and optimize them into reusable methods. This helps reduce code duplication, improve maintainability, and streamline the custom action library across the project.\\
   <Image src="https://s3-ap-south-1.amazonaws.com/ind-cdn.freshdesk.com/data/helpdesk/attachments/production/1070044041101/original/2KtESPL1ksuUIeHCLqZfgx4muqIeKYO6yA.png?1781519058" width="857" height="483" />

All identified duplicate methods are replaced with reference calls to the consolidated custom actions, reducing code duplication and improving maintainability. Click Done to close the pop-up and return to the analysis report.

     - You can add custom actions using different methods. Following are the ways to add custom actions in .
       - You can reuse the custom actions for dynamic Xpaths.\
         \
         When configuring a custom utility method for dynamic XPaths, use the following configuration code:\
         \\
         ```bash
         While creating method use this format in method name text field<method name>(XPath)

         In this code, XPath is the mandatory keyword . Ensure not to replace it.


         ```
       - If you wish to pass parameters to the same code, then use the following configuration code:
         ```bash
         While creating method use this format in method name text field <method name>(object, param)

         In this code, parameter can be an argument.
         ```
       - If you wish to pass without any parameter or dynamic XPaths, use the following configuration code.
         ```bash
         While creating method use this format in method name text field<method name>( )

         ```
       - If you wish to use an assertion, use the following configuration code:
         ```bash
         While creating method use this format in method name text field<method name> (assertion).

         ```
       - If you wish to pass only parameters, use the following code:
         ```bash
         While creating method use this format in method name text field<method name>(param)
         ```

  If a user creates a custom action with the same name as an existing default action, the system displays a warning message saying "A default action with this name already exists. Continuing will replace the default action with the custom action in all existing configurations.
</Callout>

#### Hiding a custom action

\
To hide a custom action:\
Navigate to Settings>>Feature File Settings, select Hide Custom Action checkbox and click on update.

<Image src="https://s3-ap-south-1.amazonaws.com/ind-cdn.freshdesk.com/data/helpdesk/attachments/production/1070027276099/original/XNGhHvNiU9jPUJt5fqi_dAI1JXXf_5lH6g.png?1753266447" width="1266" height="618" />

#### Editing a custom action name

To Edit a custom action:\
Navigate to Action List>>Custom Action List, Click on edit icon on Custom Action for which action name needs to be changed, change the action and click submit.

<Image src="https://s3-ap-south-1.amazonaws.com/ind-cdn.freshdesk.com/data/helpdesk/attachments/production/1070032280358/original/Uirzsq0N8Q453mrQggpHRwFCQPJRPjsG5Q.png?1761635763" width="771" height="639" />
